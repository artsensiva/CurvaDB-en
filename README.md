# CurvaDB

Хранилище GPS-траекторий на кубических B-сплайнах с поиском ближайших
соседей по дискретной метрике Фреше.

## Установка

```bash
python3 -m venv venv
venv/bin/pip install -r requirements.txt
```

Данные — GeoLife Trajectories 1.3 (`data/geolife/<user_id>/Trajectory/*.plt`),
в репозиторий не входят (см. `.gitignore`).

## Запуск бенчмарка

```bash
venv/bin/python benchmarks/step0.py
```

Сравнивает на одних и тех же треках сырую ломаную, DP-ломаную
(Дуглас-Пекер) и кубический сплайн: сначала прогон на 50 треках с
выводом времени, затем на 200 — с записью `benchmarks/results/step0.md`
и `benchmarks/results/step0.csv`.

```bash
venv/bin/pytest tests/traj/ -o addopts=""
```

## Результаты (step0, 200 треков, tol = 10 м)

Длина треков: min=55, median=412, max=1979, mean=576 точек.
Среднее число вершин DP-ломаной: 52.1, контрольных точек сплайна: 125.8.
Несошедшихся фиттингов сплайна: 0/200.

| Метрика | raw | DP-ломаная | сплайн |
|---|---|---|---|
| Байт/трек (float64) | 9224 | **833** | 3052 |
| Latency top-10, полный перебор, p50 (мс) | 35.7 | **1.5** | 1.7 (same-count) / 255.8 (arclen) |
| Latency top-10, полный перебор, p95 (мс) | 210.7 | **2.5** | 3.3 (same-count) / 3050.4 (arclen) |
| Recall@10 vs Фреше на raw | 1.0 (эталон) | **0.997** | 0.707 |
| Ошибка скорости, м/с (медиана) | — | 1.519 | **0.875** |
| Ошибка ускорения, м/с² (медиана) | — | 0.179 | **0.152** |

Ошибка скорости/ускорения — относительно конечных разностей по
Savitzky-Golay-сглаженному сырому треку. DP-ломаная кусочно-линейна,
поэтому её ускорение между вершинами тождественно 0 — её ошибка
показывает величину реального ускорения, которое ломаная принципиально
не может передать.

**Вывод**: DP-ломаная выигрывает у сплайна по байтам, latency и
recall@10 — с большим отрывом. Сплайн выигрывает только на одной оси:
он точнее восстанавливает скорость и ускорение. Подробности и
методика — в [benchmarks/results/step0.md](benchmarks/results/step0.md).

## Известные конкуренты

- **PostGIS** ([`ST_FrechetDistance`](https://postgis.net/docs/ST_FrechetDistance.html)) —
  дискретная метрика Фреше как встроенная функция SQL над `geometry`;
  готовое индустриальное решение без необходимости писать свою ДП.
- **[MobilityDB](https://mobilitydb.com/)** — расширение PostgreSQL/PostGIS
  для траекторных данных (`tgeompoint` и т.п.), с временными операциями,
  индексами и метриками схожести из коробки.
- **Map-matching** (например, [Valhalla](https://github.com/valhalla/valhalla),
  [OSRM](https://project-osrm.org/)) — привязка GPS-трека к дорожной сети;
  другой подход к сжатию/представлению траектории, снимающий часть шума
  за счёт внешней информации о графе дорог, а не только геометрии трека.
