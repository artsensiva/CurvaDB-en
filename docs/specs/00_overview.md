# Продукты на основе кривых и поверхностей: отбор и технические задания

Этот комплект описывает четыре продукта, отобранных из обсуждения CurvaDB, и даёт по каждому
техническое задание, которое можно поэтапно выполнять с ИИ-агентом (Claude Code) с проверяемым
результатом.

## 0. Что здесь означает «гарантированный результат»

Гарантировать можно только то, что проверяется. Поэтому гарантия в этих заданиях — это:

1. **Математическая гарантия корректности** там, где она доказуема (границы ошибки, отсутствие
   пропусков в запросах), подтверждённая тестами свойств на тысячах случаев.
2. **Критерии приёмки, зафиксированные до разработки**, с числами. Агент не может их менять.
3. **Критерии остановки**: при каком результате направление закрывается.

Рыночный успех не гарантируется ничем. Востребованность ниже — экспертная оценка, а не данные.
Перед продуктовым кодом по каждому направлению нужны 8–10 интервью (см. раздел 6).

## 3. Общее математическое ядро `certigeo`

Все четыре продукта опираются на один набор алгоритмов. Его нужно сделать первым и покрыть
тестами свойств: это снижает риск всех остальных этапов.

### 3.1. B-сплайны и NURBS

Кривая степени `p`: `C(u) = Σ_i N_{i,p}(u) P_i`, узловой вектор `U = {u_0 ≤ … ≤ u_{n+p+1}}`.
Рациональная (NURBS): `C(u) = Σ N_{i,p}(u) w_i P_i / Σ N_{i,p}(u) w_i`, веса `w_i > 0`.
Поверхность: тензорное произведение по `(u, v)`.

**Вставка узла (алгоритм Бёма).** Вставка `ū ∈ [u_k, u_{k+1})`:
`Q_i = α_i P_i + (1 − α_i) P_{i−1}`, где `α_i = 1` при `i ≤ k − p`, `α_i = 0` при `i ≥ k + 1`,
иначе `α_i = (ū − u_i)/(u_{i+p} − u_i)`. Для NURBS операция выполняется в однородных
координатах `(w P, w)`.

**Выделение Безье-сегментов.** Каждый внутренний узел вставляется до кратности `p`; между
соседними различными узлами получается сегмент Безье с `p + 1` контрольными точками.

**Разбиение де Кастельжо.** Сегмент Безье делится в `t = 1/2` на два, с новыми контрольными
точками. Отклонение контрольного многоугольника от кривой убывает как `O(h²)`, поэтому каждое
деление уточняет оценки примерно в 4 раза.

### 3.2. Свойство выпуклой оболочки и сертификаты

Для полиномиального сегмента Безье, а также рационального при `w_i > 0`, кривая (поверхность)
лежит в выпуклой оболочке своих контрольных точек. Следствия, используемые во всех продуктах:

- **Сертификат «кривая внутри трубки».** Капсула (множество точек на расстоянии `≤ ε` от
  отрезка) выпукла. Если все контрольные точки сегмента лежат в капсуле, весь сегмент лежит в ней.
- **Нижняя граница расстояния.** `dist(p, S) ≥ dist(p, conv(P)) ≥ dist(p, AABB(P))`.
- **Верхняя граница расстояния.** `dist(p, S) ≤ |p − S(u*, v*)|` для любой вычисленной точки.
- **Границы производных.** Производная Безье — Безье степени `p − 1` с точками
  `p (P_{i+1} − P_i)`; её норма ограничена максимумом норм этих точек. Отсюда строгая оценка
  кривизны: `κ ≤ max|C''| / min|C'|²`, где `min|C'|` — расстояние от нуля до оболочки
  контрольных точек производной (если оболочка не содержит ноль).

### 3.3. Непрерывная метрика Фреше

Используется непрерывная, а не дискретная метрика: дискретная зависит от плотности точек
(урок step0). Решение «`d_F(P, Q) ≤ ε`?» — алгоритм Альта–Годау через пространство
свободы за `O(nm)`; расстояние — бисекцией по `ε`. Для ломаной и одного отрезка решение
занимает `O(m)`.

### 3.4. Строгость вычислений с плавающей точкой

- Все сертификаты вычисляются с запасом `δ = 64 · ε_machine · L`, где `L` — характерный размер.
- Контрольная проверка: выборочно пересчитывать сертификаты интервальной арифметикой
  (`python-flint`, тип `arb`) и сравнивать.
- Эталоны с аналитической истиной (окружность, сфера, цилиндр, тор) обязательны в тестах.

### 3.5. Состав ядра

```
certigeo/
  bspline.py      # вычисление, производные, Бём, выделение Безье, де Кастельжо (кривые)
  nurbs_surf.py   # то же для поверхностей, однородные координаты
  hull.py         # AABB/OBB контрольных сеток, капсулы, проверка «внутри выпуклого»
  bounds.py       # строгие границы расстояния, производных, кривизны
  frechet.py      # Альт–Годау: решение и расстояние, ломаная–отрезок за O(m)
  interval.py     # обёртка python-flint для контрольных пересчётов
  tests/          # hypothesis: свойства на случайных кривых и поверхностях
```

Приёмка ядра: 100% тестов свойств на 10 000 случайных кривых и 2 000 поверхностей;
вставка узлов не меняет кривую (отклонение `≤ 1e-12 · L`); сертификаты не нарушаются ни на одном
из `10⁶` проверочных вычислений; совпадение с `scipy.interpolate.BSpline` до `1e-12`.

## 4. Общий стек

- **Python 3.12** в отдельном окружении (многие геометрические колёса ещё не собраны для 3.14):
  `uv python install 3.12 && uv venv --python 3.12`.
- `numpy`, `scipy`, `numba` — вычисления; `hypothesis`, `pytest` — тесты свойств; `ruff`,
  `mypy` — качество; `typer` — CLI; `pydantic` — конфигурации; `matplotlib`/`pyvista` — отчёты.
- **Rust** (через `PyO3`/`maturin`) — только на втором этапе для горячих циклов, после того как
  Python-версия прошла приёмку. Для P3 возможно расширение PostgreSQL через `pgrx`.
- GitHub Actions: тесты, линтеры, проверка, что файлы приёмки не изменены.

## 5. Как вести разработку с ИИ

### Структура репозитория

```
docs/specs/P1_certipath_cnc.md …          # эти задания (неизменяемые разделы «Приёмка»)
docs/prompts/<продукт>_M<n>.md        # короткие промпты на этап
docs/reviews/<продукт>_M<n>_review.md # ревью постановки после этапа
results/<продукт>/M<n>.md             # отчёты этапов
```

### Цикл этапа

1. Промпт этапа ссылается на спецификацию и называет только пункты этого этапа.
2. Агент показывает план, получает «ок», работает с коммитом после каждого пункта.
3. Агент пишет отчёт с числами и сравнением с критериями.
4. **Ревью постановки** (отдельная сессия или человек) по чек-листу:
   - не подменил ли агент метрику или соперника;
   - нет ли совпадающих чисел у методов, которые должны различаться;
   - не стало ли прошлое исправление ограничением;
   - соответствует ли проверка месту использования гарантии;
   - не изменены ли критерии приёмки.
5. Решение: следующий этап, доработка или остановка по критерию остановки.

### Шаблон промпта этапа

```
Выполни этап M<n> из docs/specs/<файл>.md. Контекст — CLAUDE.md.
Раздел «Приёмка» не менять. Новые зависимости — только из раздела «Стек».
Коммит после каждого пункта, незавершённое — в TODO.md.
В конце — results/<продукт>/M<n>.md с таблицей «критерий / порог / факт / выполнен».
Уточняющих вопросов не задавать, если ответ есть в спецификации.
Сначала короткий план, жди «ок».
```

## 6. Порядок работ

1. **Ядро `certigeo`** (2–3 сессии) — нужно всем.
2. **P3 CertiTrack** (3–4 сессии) — проверяет ядро на уже имеющихся данных GeoLife.
3. Параллельно — **интервью**: технологи ЧПУ (P1), инженеры контроля качества (P2),
   робототехники (P3, P4). Порог: 3 из 10 независимо называют проблему, которую решает продукт.
4. **P2 или P1** — по результатам интервью.
5. **P4** — только при подтверждённом спросе.

## 7. Общее определение «готово»

- Все критерии приёмки этапа выполнены, отчёт с числами закоммичен.
- Тесты проходят, покрытие ядра не ниже 90% строк.
- Ревью постановки проведено, замечания закрыты или вынесены в TODO.md с обоснованием.
- Воспроизведение одной командой описано в README.
