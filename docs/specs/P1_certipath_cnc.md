# P1. CertiPath — оптимизатор траекторий ЧПУ с сертифицированной точностью

## 1. Продукт

**Что делает.** Принимает управляющую программу из CAM (траектория центра инструмента из
множества коротких отрезков G01) и параметры станка. Выдаёт гладкую траекторию с
оптимальным по времени профилем подачи и **сертификатом**: доказанная граница отклонения от
исходной траектории и соблюдение ограничений скорости, ускорения и рывка по каждой оси.

**Кому.** Производства сложных поверхностей: пресс-формы, аэрокосмические детали, медицинские
импланты, турбинные лопатки. Пользователь — технолог-программист ЧПУ.

**Ценность.** Меньше времени станка при том же допуске, меньше граней на поверхности из-за
торможения на стыках отрезков, документальное подтверждение точности пути.

**Существующие решения.** Сглаживание в CAM-системах, сплайновая интерполяция и планирование
подачи с окном просмотра в высококлассных системах ЧПУ, оптимизация подачи в программах
симуляции. **Отличие:** глобальная офлайн-оптимизация всей траектории плюс строгий сертификат
отклонения, а не проверка выборкой.

**Честное ограничение.** Точность детали определяется ещё динамикой станка, тепловыми
деформациями, отжимом инструмента и вибрациями. Продукт сертифицирует **командную траекторию**,
а ошибку слежения только моделирует и отчитывает отдельно.

**Границы v1.** 3 оси, центр инструмента (компенсация радиуса уже выполнена в CAM),
обработка без 5-осевой кинематики и без проверки зарезов по модели детали.

## 2. Математическая модель

### 2.1. Бюджет отклонения

```
ε_total = ε_fit + ε_sample   (сертифицируются)
ε_lag                        (моделируется, отчитывается отдельно)
```

- `ε_fit` — отклонение гладкой траектории от исходной ломаной.
- `ε_sample` — отклонение из-за дискретизации команды с периодом контроллера `T_s`.
- `ε_lag` — контурная ошибка слежения сервопривода по модели.

### 2.2. Гладкая траектория и сертификат `ε_fit`

1. Исходная ломаная `L` (вершины `V_0…V_n`) разбивается на участки в **особых точках**: угол
   между соседними отрезками больше `θ_corner` (по умолчанию 30°), остановки и смены режима
   (G0). В особых точках траектория не сглаживается — там допускается остановка или локальное
   скругление с отдельной границей.
2. На каждом участке строится кубический B-сплайн `C(u)` класса C² методом наименьших
   квадратов по вершинам (параметризация длиной хорды), число узлов подбирается.
3. **Сертификат.** Сплайн раскладывается на Безье-сегменты. Сегмент сертифицирован с радиусом
   `ε`, если все его контрольные точки лежат в капсуле радиуса `ε` вокруг **одного** отрезка
   `[V_k, V_{k+1}]`: капсула выпукла, значит в ней лежит и весь сегмент. Объединение капсул
   соседних отрезков не выпукло, поэтому сегмент, пересекающий стык, делится де Кастельжо
   (до `d_max = 12` уровней), пока каждая часть не попадёт в капсулу своего отрезка. Если деление
   не помогает — добавляется узел или уменьшается сглаживание. Радиус для сегмента берётся
   минимальным: максимум по контрольным точкам расстояния до выбранного отрезка.
4. **Обратное направление (покрытие).** Проверяется, что каждая вершина `V_k` находится на
   расстоянии `≤ ε` от сплайна (верхняя граница через вычисленную точку с уточнением Ньютоном)
   и что параметр монотонно проходит отрезки (нет «срезания» петель).
5. Итог: `ε_fit` — максимум сертифицированных радиусов по сегментам.

### 2.3. Оптимальная подача (SOCP)

Параметр `u ∈ [0, 1]`, сетка `u_0 < … < u_N` (`N` порядка 10 точек на Безье-сегмент).
Переменные: `b_i = u̇²`, `a_i = ü`. Связь: `db/du = 2a`, дискретно `b_{i+1} − b_i = 2 a_i Δu`.

Ограничения для каждой оси `j` в каждой точке `i`:

- скорость: `x_j'(u_i)² · b_i ≤ V_j²` (линейно по `b`);
- ускорение: `|x_j''(u_i) · b_i + x_j'(u_i) · a_i| ≤ A_j` (линейно);
- подача: `|C'(u_i)|² · b_i ≤ F_max²`;
- контурная ошибка слежения (модель запаздывания первого порядка с постоянной `T` на каждой оси):
  `κ_i · |C'(u_i)|² · b_i · T² / 2 ≤ ε_lag_target` (линейно по `b`);
- граничные условия: `b_0 = b_N = 0` на концах участка или согласованная скорость в особой точке.

Цель — время: `T_total = Σ 2Δu / (√b_i + √b_{i+1})`. Выпуклая формулировка:
вспомогательные `c_i` с `c_i² ≤ b_i` (конус второго порядка) и `d_i` с
`d_i · (c_i + c_{i+1}) ≥ 2Δu` (вращённый конус), минимизировать `Σ d_i`.
Решатель: CVXPY + Clarabel.

### 2.4. Рывок: последовательная выпуклая оптимизация

Рывок по оси: `j = u̇ · (x''' · b + 3 x'' · a + x' · da/du)`. При фиксированном `u̇` из
предыдущей итерации ограничение `|j| ≤ J` линейно по `(b, a, da/du)`. Выполнить 5–10 итераций с
доверительной областью `|b − b_prev| ≤ ρ · b_prev`.

**Гарантированная выполнимость.** После оптимизации рывок проверяется на итоговой команде.
Если где-то нарушен, траектория во времени растягивается с коэффициентом `λ ≥ 1`: скорость
делится на `λ`, ускорение на `λ²`, рывок на `λ³`. Сначала пробуется локальное растяжение с
гладким переходом `λ(u)` (его производные дают дополнительные слагаемые, поэтому результат
перепроверяется); если перепроверка не проходит, применяется глобальное постоянное `λ`, которое
восстанавливает ограничения всегда. Поэтому выход **гарантированно** допустим, в худшем случае
ценой части выигрыша по времени.

### 2.5. Сертификат `ε_sample`

Команда выдаётся с периодом `T_s` (по умолчанию 1 мс). Отклонение хорды между соседними
командными точками от кривой не больше `v_max² · T_s² · κ_max / 8`, где `κ_max` — строгая
верхняя граница кривизны на Безье-сегменте (раздел 3.2 обзора). Суммируется в `ε_total`.

### 2.6. Модель станка для симуляции

Каждая ось — привод с запаздыванием первого порядка `T` (по умолчанию 5 мс) и ограничениями
`V_j, A_j, J_j`. Симуляция с шагом `T_s / 10`. Контурная ошибка — расстояние фактической точки
до командной траектории (строго, через проекцию на сплайн).

## 3. Базовые соперники

1. **Планировщик с окном просмотра и допуском на стыке** (схема «junction deviation», как в
   открытых прошивках станков): трапецеидальные профили на каждом отрезке, скорость на стыке
   `v = √(A · δ · s / (1 − s))`, где `s = sin(θ/2)`, `δ` — допуск скругления, окно 32 отрезка.
2. **То же с S-профилем** (ограничение рывка), чтобы сравнение по рывку было честным.

Оба соперника и CertiPath прогоняются через **одну и ту же** модель станка из 2.6.

## 4. Данные для проверки

1. **Синтетические поверхности:** седло `z = 0.1(x² − y²)`, сумма гауссовых бугров, случайная
   бикубическая B-сплайн поверхность, полусфера. Размер 100×100 мм.
2. **Генерация траекторий «как в CAM»:** зигзаг и спираль с шагом 0.2–1 мм, центр шарового
   инструмента, хордовый допуск CAM `ε_CAM ∈ {1, 5, 10} мкм` → программы из 5 000–100 000 G01.
3. **Контурные тесты:** окружность, ромб, квадрат (по мотивам тестовой детали NAS 979),
   спираль Архимеда.
4. **Эталоны с аналитической истиной:** окружность и винтовая линия — отклонение считается
   точно.

## 5. Архитектура

```
certipath/
  io/gcode_parser.py      # подмножество: G0, G1, G2, G3, F, единицы; выход — ломаные с атрибутами
  io/gcode_writer.py      # плотные G1 с F; опционально G5.2/G5.3 (NURBS) для LinuxCNC
  segment.py              # особые точки, участки
  fit.py                  # МНК B-сплайн, подбор узлов, сертификат ε_fit (использует certigeo)
  feed_socp.py            # SOCP по 2.3
  feed_jerk.py            # SCP по 2.4 + масштабирование времени
  sample.py               # командная дискретизация, ε_sample
  sim/machine.py          # модель осей
  sim/contour.py          # строгая контурная ошибка
  baselines/junction.py   # соперник 1
  baselines/scurve.py     # соперник 2
  report/certificate.py   # JSON-сертификат + HTML-отчёт
  cli.py                  # certipath optimize in.nc --machine m.yaml --tol 0.005 -o out.nc
```

**Сертификат (JSON).** Версия, хэш входной программы, параметры станка, `ε_fit`, `ε_sample`,
`ε_total`, модельная `ε_lag`, максимумы `|v|, |a|, |j|` по осям, время цикла, список участков с
их сертификатами.

## 6. Стек

Python 3.12, `numpy`, `scipy`, `numba`, `cvxpy` + `clarabel`, `pydantic`, `typer`, `pytest`,
`hypothesis`, `matplotlib`, `jinja2`; ядро `certigeo`. Этап 2: Rust для симуляции и сертификатов.

## 8. Приёмка (не менять)

| № | Критерий | Порог |
|---|---|---|
| A1 | Корректность сертификата: в симуляции с частотой в 100 раз выше `1/T_s` отклонение командной траектории от ломаной не превышает `ε_fit + ε_sample` | 100% точек, запас `1e-9` мм |
| A2 | Плотность сертификата: `(ε_fit + ε_sample) / измеренное отклонение` | медиана ≤ 2, p99 ≤ 5 |
| A3 | Ограничения осей на итоговой команде | ноль нарушений сверх `1e-6` относительных |
| A4 | Эффективность на наборе поверхностей при равном `ε_total` | время цикла ≤ 0.85 × лучшего соперника |
| A5 | Модельная контурная ошибка | ≤ `ε_lag_target` в 99.9% точек |
| A6 | Аналитические эталоны | измеренное отклонение совпадает с аналитическим до `1e-9` мм |
| A7 | Время расчёта | 50 000 отрезков ≤ 30 мин на 6 ядрах |

**Остановка.** Если после M3 время цикла не лучше 0.95 × лучшего соперника — направление
закрывается: гарантии без выигрыша по времени не окупят внедрение. Если медиана A2 хуже 5 —
сертификаты бесполезно грубы, пересмотр подхода.

## 9. Тесты свойств (обязательные)

- Вставка узла не меняет кривую; Безье-сегменты воспроизводят исходный сплайн.
- Для случайных ломаных и сплайнов: если сертификат выдан, 10⁵ случайных точек сегмента лежат
  в капсуле.
- Масштабирование времени с `λ` делит скорость, ускорение, рывок на `λ, λ², λ³`.
- Решение SOCP допустимо при проверке ограничений независимым кодом.
- Смещение и поворот программы не меняют время цикла и сертификат (инвариантность).

## 10. Риски

- **Реальная ценность ограничена динамикой станка** — снижается интервью и последующими
  испытаниями с партнёром на реальном станке и координатно-измерительной машине.
- **Форматы сплайнов у систем ЧПУ закрыты и различаются** — v1 выдаёт плотные G1 (универсально)
  и G5.2 для LinuxCNC; интеграция с конкретными контроллерами — отдельный проект.
- **SCP по рывку может сходиться медленно** — страховка масштабированием времени гарантирует
  допустимость, теряется только часть выигрыша.
