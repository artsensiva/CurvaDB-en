# P3. CertiTrack — хранилище траекторий с гарантированно корректным поиском по Фреше

## 1. Продукт

**Что делает.** Хранит большие коллекции траекторий в сжатом виде вместе с **сертификатом**
погрешности каждой траектории. Отвечает на запросы «все траектории на расстоянии Фреше не
больше `r` от заданной» и «`k` ближайших» так, что результат **совпадает** с полным перебором по
исходным данным: ноль пропусков и ноль лишних. Исходные данные при этом читаются только для
малой доли кандидатов.

**Кому.** Команды робототехники и беспилотного транспорта (поиск похожих ситуаций в логах для
разбора инцидентов и сбора обучающих сценариев), логистика, спортивная аналитика, морская и
авиационная аналитика траекторий.

**Ценность.** Существующие системы либо ищут приближённо (нет гарантии полноты), либо считают
точную метрику по исходным данным (медленно). Для разбора инцидентов пропуск похожего случая
дорог. CertiTrack даёт точный ответ быстрее за счёт доказуемых границ.

**Существующие решения.** Функции расстояния Фреше в PostGIS, MobilityDB, академические
индексы траекторий, решения соревнования ACM SIGSPATIAL GIS Cup 2017 (поиск по диапазону
Фреше). **Отличие:** сжатое хранение с сертификатами погрешности, которые напрямую используются
в фильтрации, и формальная гарантия точного ответа.

**Уроки CurvaDB.** Здесь сжатие — не цель, а средство. Используется **непрерывная** метрика
Фреше (дискретная зависит от плотности точек). Представление по умолчанию — ломаная:
сплайны в CurvaDB не выиграли; поддержка сплайнов остаётся точкой расширения.

## 2. Математическая модель

### 2.1. Метрика

Непрерывное расстояние Фреше `d_F` между ломаными — псевдометрика, удовлетворяет неравенству
треугольника. Решение `d_F(P, Q) ≤ ε` — алгоритм Альта–Годау за `O(nm)`; для ломаной и одного
отрезка — за `O(m)` проходом по достижимым интервалам.

### 2.2. Упрощение с сертификатом

Для траектории `T` строится упрощение `T'` из подмножества её вершин так, что
`d_F(T, T') ≤ ε`:

- жадное расширение отрезка от вершины `i`: экспоненциальный, затем двоичный поиск наибольшего
  `j`, для которого `d_F(T[i..j], [T_i, T_j]) ≤ ε` (решение за `O(j − i)`);
- так как для последовательной склейки частей `d_F(T, T') ≤ max` по частям, сертификат всей
  траектории равен `ε`; фактическое значение `ε_T = max` по частям уточняется бисекцией и
  сохраняется (оно меньше или равно `ε`).

Сложность `O(n log n)` на траекторию.

### 2.3. Хранимые данные на траекторию

- вершины `T'` (координаты и время): квантование до 1 см и 10 мс, дельта-кодирование, zstd;
- `ε_T` с запасом на округление: `ε_T := ε_T + 2 · 0.005 м`;
- ограничивающий прямоугольник исходной `T`, начальная и конечная точки исходной `T`;
- ссылка на исходную траекторию в холодном хранилище.

### 2.4. Границы для запроса

Запрос `q` (упрощается так же, `q'`, `ε_q`), радиус `r`. Для кандидата `T`:

1. **Концы:** `d_F(q, T) ≥ max(|q_0 − T_0|, |q_end − T_end|)`. Если больше `r` — отбросить.
2. **Прямоугольники:** каждая точка `q` сопоставлена точке `T`, лежащей в прямоугольнике `T`,
   поэтому `d_F(q, T) ≥ max_i dist(q_i, MBR(T))`; симметрично по вершинам `T'`, которые являются
   вершинами `T`. Если больше `r` — отбросить.
3. **Сертифицированный интервал:**
   `d_F(q, T) ∈ [d_F(q', T') − ε_q − ε_T, d_F(q', T') + ε_q + ε_T]`.
   Вместо расстояния используются дешёвые решения:
   - если `d_F(q', T') ≤ r − ε_q − ε_T` — **принять** без исходных данных;
   - если не `d_F(q', T') ≤ r + ε_q + ε_T` — **отбросить**;
   - иначе — **уточнить**: точное решение `d_F(q, T) ≤ r` по исходным траекториям.
4. **k ближайших:** обход кандидатов в порядке нижней границы, текущий порог — `k`-е лучшее
   значение верхней границы; уточнение только пока нижняя граница кандидата меньше порога;
   итог проверяется точными расстояниями для граничных кандидатов.

Все три правила строгие, поэтому ответ совпадает с полным перебором.

### 2.5. Индексы

- R-дерево по прямоугольникам траекторий, расширенным на `r` при запросе;
- KD-дерево по начальным и конечным точкам: кандидат должен иметь начало в круге радиуса `r`
  вокруг `q_0` и конец в круге вокруг `q_end` (пересечение двух выборок);
- для временных запросов — дополнительный фильтр по интервалу времени.

## 3. Базовые соперники

1. **Полный перебор** точным решением по исходным траекториям (эталон результата).
2. **Классический фильтр** «концы + прямоугольники + точное решение по исходным» без
   сертифицированного сжатия (эталон скорости).
3. Для справки: запрос через функцию расстояния Фреше в PostGIS на той же выборке (если
   развёрнут Docker), с оговоркой, что это другая система.

## 4. Данные для проверки

1. **GeoLife** (уже есть): очищенные поездки по правилам CurvaDB, все сегменты, не только 585.
2. **T-Drive** (открытый набор траекторий такси Пекина) — масштаб до сотен тысяч поездок.
3. **Синтетические почти-дубликаты с известным расстоянием:** исходные траектории плюс копии
   с контролируемыми искажениями (сдвиг части, шум, прореживание, изменение скорости), для
   которых точное `d_F` вычисляется заранее; это даёт запросы с ответами у самой границы `r`.
4. **Набор соревнования GIS Cup 2017**, если доступен.

## 5. Архитектура

```
certitrack/
  frechet/decide.py       # Альт–Годау, numba; ломаная–отрезок O(m)
  frechet/distance.py     # бисекция по решению с заданной точностью
  simplify/certified.py   # 2.2
  store/encode.py         # квантование, дельты, zstd
  store/parquet_store.py  # разделы Parquet: приближения, сертификаты, метаданные
  store/cold.py           # исходные траектории (Parquet или файлы)
  index/rtree_index.py    # rtree
  index/endpoints.py      # KD-деревья scipy
  query/range.py          # 2.4, пункты 1–3
  query/knn.py            # 2.4, пункт 4
  bench/                  # генератор запросов, соперники, отчёт
  api.py                  # Python API: Store.add, Store.range(q, r), Store.knn(q, k)
  cli.py                  # certitrack ingest / range / knn / bench
```

Этап 2: ядро на Rust (`frechet`, `simplify`, `query`) с привязками PyO3; расширение PostgreSQL
через `pgrx` с функциями `certitrack_range(geom, r)` и `certitrack_knn(geom, k)`.

## 6. Стек

Python 3.12, `numpy`, `numba`, `scipy`, `rtree`, `pyarrow`, `zstandard`, `typer`, `pytest`,
`hypothesis`, `mpmath` (эталонные вычисления высокой точности); ядро `certigeo` (модуль
`frechet`). Этап 2: Rust, `pyo3`, `maturin`, `pgrx`.

## 8. Приёмка (не менять)

| № | Критерий | Порог |
|---|---|---|
| C1 | Точность ответа по диапазону против полного перебора | 0 пропусков и 0 лишних на 1000 запросах × `r ∈ {50, 200, 1000} м` × корпус 10 000 траекторий, включая почти-дубликаты у границы |
| C2 | Корректность сертификатов | `ε_T ≥ d_F(T, T')`, вычисленного с точностью 1e-6 м, для 100% траекторий |
| C3 | Эффективность против соперника 2 при идентичных ответах | уточнений по исходным ≤ 10% кандидатов после пространственного фильтра; задержка p95 ≤ 0.5× соперника |
| C4 | Объём | приближения и сертификаты ≤ 20% от квантованных исходных при `ε = 5 м` |
| C5 | k ближайших | совпадение с полным перебором для `k = 10` на 1000 запросах |
| C6 | Масштаб | 200 000 траекторий T-Drive: построение ≤ 2 ч, p95 запроса по диапазону `r = 200 м` ≤ 1 с на 6 ядрах |

**Остановка.** Если после M2 задержка p95 не лучше 0.8× соперника 2 — сертифицированное
сжатие не окупается; продукт сводится к библиотеке точного Фреше, дальнейшая разработка
не ведётся.

## 9. Тесты свойств (обязательные)

- Решение Альта–Годау согласовано с расстоянием: `d ≤ ε ⇔ decide(ε)` на случайных парах.
- Неравенство треугольника на случайных тройках (с допуском 1e-9).
- `d_F(T, T') ≤ ε_T` для случайных траекторий и упрощений.
- Нижние границы из 2.4 не превышают точного расстояния.
- Инвариантность результатов к сдвигу и повороту всего корпуса и запроса.
- Изменение порядка добавления траекторий не меняет ответы.

## 10. Риски

- **Квадратичная сложность точного решения** на длинных траекториях — ограничивать длину
  сегментацией и уточнять только малую долю; на Rust ускорение в 10–50 раз.
- **Спрос** — ценность проявляется у команд, которым пропуск похожего случая дорог; проверить
  интервью с робототехникой и беспилотным транспортом.
- **Время в метрике** — v1 пространственная; пространственно-временная метрика — отдельный
  этап.
